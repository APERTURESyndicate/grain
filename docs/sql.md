# GRAIN 1.2 — SQL

Дополнение к [ядру стандарта](README.md). Схема живёт дольше любого сервиса, который её читает, поэтому имена в ней стоят дороже, чем в коде.

## Регистр и число

- Всё `snake_case`, ключевые слова в нижнем регистре.
- **Таблица — множественное число:** `tracks`, `user_sessions`. Строка таблицы — один трек, таблица — все.
- **Колонка — единственное:** `track_id`, `cover_url`.
- Связующая таблица — оба домена по алфавиту: `playlist_tracks`.

## Колонки

| Правило | Пример |
|---|---|
| Первичный ключ — всегда `id` | `id uuid primary key` |
| Внешний ключ — `<домен>_id` | `track_id`, `owner_id` |
| Момент времени — суффикс `_at`, тип `timestamptz` | `created_at`, `published_at`, `deleted_at` |
| Длительность — `_ms` / `_sec` | `duration_sec`, `timeout_ms` |
| Деньги — `_cents`, целое | `price_cents bigint` |
| Размер — `_bytes` | `file_size_bytes` |
| Счёт — `_count` | `play_count` |
| Доля — `_ratio` (0..1) / `_pct` (0..100) | `completion_ratio` |
| Булева — `is_` / `has_` / `can_` | `is_public`, `has_lyrics` |

**Число без единицы в схеме — ошибка.** `duration integer` не отвечает на вопрос, в чём измеряется; `duration_sec integer` отвечает, и ответ переживёт автора.

`timestamptz`, не `timestamp`: время без зоны в распределённой системе — это время неизвестно где.

## Индексы и ограничения

| Объект | Префикс | Пример |
|---|---|---|
| Индекс | `idx_` | `idx_tracks_owner_id` |
| Уникальный индекс | `uq_` | `uq_tracks_slug` |
| Первичный ключ | `pk_` | `pk_tracks` |
| Внешний ключ | `fk_` | `fk_tracks_owner_id` |
| Check | `ck_` | `ck_tracks_price_cents_positive` |

Имя объекта читается как «что это → где → по чему». Полное имя без сокращений: имена индексов встречаются в планах запросов и в логах блокировок, где угадывать некогда.

## Миграции

Имя файла: `<номер>_<глагол>_<предмет>.sql` — глагол из того же словаря.

```
0032_create_track_covers.sql
0033_ensure_tracks_slug_unique.sql
0034_archive_legacy_playlists.sql
```

**DDL идемпотентен:** `if not exists`, `on conflict do nothing`. Миграция, применённая дважды, обязана дать тот же результат — иначе её нельзя накатить руками на прод после сбоя.

**Одна миграция — одно изменение.** Файл, меняющий три несвязанные таблицы, невозможно откатить частично.

**Удаления нет.** Строка помечается `deleted_at timestamptz`; физический `delete` остаётся за задачами ретенции, а не за прикладным кодом.
