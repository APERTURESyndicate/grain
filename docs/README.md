# GRAIN 1.2

**Стандарт кода APERTURESyndicate.** Зерно плёнки — то, по чему узнают носитель, не глядя на подпись.

GRAIN не про отступы и кавычки: это работа форматтера, и она не оставляет следа. GRAIN — про **имена, контракты и форму**: то, что остаётся после любого форматтера и читается как почерк. Код, написанный по GRAIN, узнаётся в чужом репозитории с одного экрана.

## Уровни

Стандарт принимается не целиком за один день. L1 и L2 отличаются **объёмом правил**, L3 — **машинной гарантией**.

| | Уровень | Что входит | Кому |
|---|---|---|---|
| **L1** | Читаемость | Глагол из словаря · единица у числа · префикс у булевых · тегированные комментарии · никаких `utils` · мёртвый код удаляется | Личный проект, первая неделя. Принимается за вечер, ломает привычки, а не архитектуру |
| **L2** | Контракты | Всё ядро: `find`/`get`, роли файлов, форма функции, модель отказов, границы и направление зависимостей | Командная работа, код живёт дольше года |
| **L3** | Дисциплина | Правила L2 плюс: проверка в CI, блокирующий pre-commit, стандарт покрывает весь код, ни одного обхода в истории | Продукт в проде, чужие люди читают код |

Уровень объявляется в `grain.synx` проекта и подтверждается машиной: заявить L2 и не проходить L2 нельзя — чекер не выдаст бейдж.

## Три принципа

**1. Закрытые словари вместо вкуса.**
Глаголы, единицы измерения, префиксы, роли файлов — конечные списки. Не «пиши понятно», а «вот 33 глагола, других нет». Спор о названии функции длится ровно столько, сколько занимает чтение таблицы.

**2. Имя — часть контракта.**
`findTrack` и `getTrack` — разные обещания, а не синонимы. Прочитав имя, ты знаешь: может ли вернуться `null`, ходит ли функция в сеть, порождает ли событие, в чём измеряется число. Это снимает половину поводов открыть тело функции.

**3. Форма — следствие ответственности, а не вкуса.**
Функция длинная не потому, что «так вышло», а потому что делает две вещи. Ограничения на вложенность, число аргументов и длину — не эстетика, а сигнализация: превысил — раздели.

## 1. Глаголы

Функция — это действие, значит имя начинается с глагола. Глагол берётся из закрытого словаря, и **каждый глагол несёт контракт**, который нельзя нарушать.

### Чтение

| Глагол | Контракт |
|---|---|
| `find*` | Может вернуть `null`. **Никогда не бросает.** Отсутствие — нормальный исход |
| `get*` | Гарантирует значение. Нет значения — бросает. Никаких `null` в типе |
| `list*` | Всегда коллекция. Пустая коллекция — не ошибка и не `null` |
| `count*` | Число. Никогда не `null` |

Одна эта пара меняет чтение кода: `const track = await findTrack(id)` — видно, что ниже будет ветка на отсутствие, не открывая функцию. `getTrack(id)` в том же месте означал бы «здесь трек обязан быть, иначе это баг».

### Границы и хранилище

| Глагол | Контракт |
|---|---|
| `read*` / `write*` | Пересечение границы I/O: сеть, диск, объектное хранилище |
| `load*` / `save*` | Агрегат целиком через хранилище (БД) |

Разделение `read`/`load` не педантизм: по имени видно, переживёт ли вызов офлайн и стоит ли его кэшировать.

### Вычисление

| Глагол | Контракт |
|---|---|
| `make*` | Чистый конструктор значения. Без I/O, без времени, без случайности |
| `derive*` | Чистое вычисление из уже имеющихся данных |
| `resolve*` | Выбор одного варианта из нескольких по правилам |
| `parse*` `format*` `encode*` `decode*` `normalize*` `sign*` `verify*` `hash*` | Преобразование формы данных: вход → выход, без состояния |

### Изменение

| Глагол | Контракт |
|---|---|
| `create*` / `delete*` | Мутация домена: меняет состояние **и** порождает событие |
| `archive*` / `restore*` | Обратимое изъятие из оборота |
| `ensure*` | Идемпотентно приводит состояние к нужному. Повторный вызов ничего не меняет |
| `assert*` | Бросает при нарушении инварианта, иначе `void`. Ничего не возвращает |
| `apply*` | Накатывает готовое изменение на цель |
| `set*` | Присваивает значение, дальше по системе ничего не происходит |

### Связь и жизненный цикл

| Глагол | Контракт |
|---|---|
| `emit*` | В шину. Адресат неизвестен и не важен |
| `send*` | Конкретному адресату. Адресат — часть имени: `sendVerifyEmail` |
| `start*` / `stop*` | Жизненный цикл процесса или подсистемы |
| `use*` `with*` `render*` | Только в UI-коде: хуки, обёртки, отрисовка |

### Запрещённые глаголы

Каждый запрещён потому, что **не сообщает действия** — он сообщает, что автор не решил, что делает функция.

| Запрещено | Вместо |
|---|---|
| `handle*` | Назови действие: `submitLogin`, `retryPayout`, `dropStaleSession` |
| `process*` | `derive*` / `apply*` / точный глагол преобразования |
| `manage*` | Функция делает больше одной вещи — раздели |
| `do*` `perform*` `execute*` `run*` | Назови действие |
| `check*` | `is*` если возвращает ответ, `assert*` если бросает |
| `init*` | `start*` для процесса, `make*` для значения |
| `update*` | `save*` / `apply*` / `set*` — что именно происходит |
| `fetch*` `retrieve*` | `read*` (I/O) / `load*` (агрегат) / `get*` |
| `calculate*` `compute*` | `derive*` |
| `generate*` `build*` `prepare*` | `make*` |
| `setup*` | `ensure*` / `start*` |
| `validate*` | `assert*` (бросает) / `parse*` (возвращает разбор) |
| `transform*` `convert*` | `derive*` / `format*` / `encode*` |
| `determine*` | `resolve*` |
| `trigger*` | `emit*` / `send*` |

> **Обработчики событий.** Функция, вызываемая по событию, называется по тому, что делает: `submitLogin`, `toggleTheme`, `retryUpload` — не `handleSubmit`. Префикс `on*` остаётся за **свойствами** (`onClick={submitLogin}`) — там он часть контракта UI-библиотеки, а не имя действия.

## 2. Имена

### Порядок слов: домен → уточнение → единица

```
trackCoverUrl          не  urlOfCover, coverURL, imageLink
sessionRefreshTtlSec   не  refreshTimeout, ttl, expiry
payoutAmountCents      не  amount, total, sum
```

Общее слева, частное справа. Такие имена сортируются в алфавитном порядке в осмысленные группы, и автодополнение по первому слову выдаёт всё про домен сразу.

### Число без единицы измерения — ошибка

Это единственное правило GRAIN, которое ловит целый класс продакшн-багов: секунды, отданные туда, где ждали миллисекунды.

| Суффикс | Смысл |
|---|---|
| `*At` | Момент времени, всегда UTC |
| `*Ms` `*Sec` `*Min` `*Hours` `*Days` | Длительность |
| `*Bytes` `*Kb` `*Mb` `*Gb` | Размер |
| `*Cents` | Деньги, всегда в минорных единицах, всегда целое |
| `*Ratio` | Доля 0..1 |
| `*Pct` | Проценты 0..100 |
| `*Count` `*Index` | Счёт и позиция |
| `*Px` `*Deg` `*Hz` `*Bpm` `*Db` | Доменные величины |

Безразмерные величины, которым суффикс не нужен: `x y z width height depth port page limit offset version priority`. Список закрыт — если твоя величина не в нём, у неё есть единица.

### Булевы — семь префиксов, других нет

`is` `has` `can` `should` `was` `will` `must`

```ts
const isPublished = track.publishedAt !== null
const hasActiveSubscription = ...
const canPublish = ...
```

`enabled`, `published`, `flag`, `status` булевым именем не являются.

### Слова, которые ничего не сообщают

Запрещены как последнее слово имени и как имя целиком:

```
data info obj object temp tmp stuff misc thing things
res ret arr str num flag val result
helper handler manager wrapper util utils
```

`userData` → `user`. `trackInfo` → `track` или `trackSummary`. `parseResult` → `parsedTrack`. Если после удаления пустого слова имя стало неотличимо от другого в той же области видимости — значит эти две сущности и правда одно и то же, либо одной из них нужно настоящее имя.

### Сокращения

Разрешены ровно эти: `id url uri db io rpc ttl utc api sql css html json jwt s3 ip dns cdn ui ms`.

Всё остальное пишется целиком: `config` не `cfg`, `request` не `req`, `message` не `msg`, `error` не `err`, `index` не `idx`, `previous` не `prev`.

**Длина имени пропорциональна области видимости.** В колбэке на две строки `t` допустимо и честно. В экспортируемом API однобуквенных имён нет.

### Самопохвала

`enhanced` `advanced` `comprehensive` `ultimate` `robust` `powerful` `seamless` `smart` `intelligent` `optimized` `improved` `modern` `simple` `easy` `quick` — в именах запрещены. Это оценка, а не описание; она устаревает в момент коммита и всегда означает «я не нашёл, чем эта версия отличается от прошлой».

## 3. Форма функции

### Воронка: четыре такта, всегда в этом порядке

```
guard      →  отсечь невозможное, выйти рано
acquire    →  добыть данные (I/O)
derive     →  посчитать (чисто, без I/O)
effect     →  записать, отправить, вернуть
```

Такты не перемешиваются. I/O внутри цикла внутри условия — не GRAIN. Если тактов оказалось два комплекта — это две функции.

```ts
export async function publishTrack(trackId: string, actorId: string): Promise<Track> {
  const track = await findTrack(trackId)                       // acquire
  if (track === null) throw makeFail('music.track.missing')    // guard
  assertCanPublish(track, actorId)                             // guard

  const published = derivePublishedTrack(track)                // derive
  await saveTrack(published)                                   // effect
  await emitTrackPublished(published)
  return published
}
```

### Числа

| Предел | Значение | Что означает превышение |
|---|---|---|
| Вложенность | 2 | Внутренний блок — отдельная функция |
| Аргументов | 3 | Дальше — один именованный объект |
| Строк в функции | 40 | Функция делает больше одного дела |
| Строк в файле | 400 | В файле больше одной роли |
| Глубина каталогов от `src/` | 3 | Иерархия глубже никем не читается |

### Правила формы

- `else` после `return` не пишется. Guard выходит, продолжение идёт левее.
- Вложенных тернарных операторов нет — это `switch` или таблица.
- Экспорт только именованный. Имя сущности одинаково на обоих концах импорта, иначе поиск по коду перестаёт работать.
- Переменная, живущая одну строку до `return`, не нужна.

## 4. Границы

Правила этой главы — про то, что чаще всего делает код невозможным для тестирования и непредсказуемым в проде. Они появились в 1.1, потому что без них стандарт остаётся стандартом про имена.

### Время, случайность и окружение — только на границе

`Date.now()`, `new Date()`, `Math.random()`, `crypto.randomUUID()`, `process.env` живут в файлах-границах (`*.entry.ts`, `*.route.ts`, `*.rpc.ts`, `*.job.ts`, `*.wire.ts`). В домен они приходят аргументом.

```ts
// было: функция зависит от часов машины и от того, какой сегодня день
export function isTrialExpired(user: User): boolean {
  return Date.now() > user.trialEndsAt.getTime()
}

// стало: чистая функция, тестируется без моков и воспроизводится по логам
export function isTrialExpired(user: User, nowMs: number): boolean {
  return nowMs > user.trialEndsAt.getTime()
}
```

Цена нарушения конкретна: тест на «истёкший триал» приходится писать через подмену системного времени, ошибка часового пояса всплывает только в проде, а баг, случившийся ночью, невозможно воспроизвести днём.

### Зависимости направлены внутрь

Домен не знает, кто его вызывает и через что ходит наружу. Роль файла определяет, что ему разрешено импортировать:

| Роль | Может импортировать |
|---|---|
| `*.pure.ts` | `pure`, `shape` |
| `*.policy.ts` | `pure`, `shape`, `policy` |
| `*.shape.ts` | `shape` |
| `*.store.ts` · `*.wire.ts` · `*.event.ts` | `shape`, `pure` и свою же роль |
| `*.route.ts` · `*.rpc.ts` · `*.job.ts` · `*.entry.ts` | всё — это границы, их работа знать обо всём |

Стрелки идут только внутрь, к домену. Как только `*.pure.ts` импортировал `*.store.ts`, чистая часть перестала быть чистой, и её больше нельзя ни протестировать без базы, ни переиспользовать.

### Независимые ожидания — параллельно

```ts
// было: два запроса по очереди, 180 мс вместо 90
const track = await findTrack(trackId)
const genres = await listGenres()

// стало
const [track, genres] = await Promise.all([findTrack(trackId), listGenres()])
```

Последовательный `await` допустим ровно тогда, когда второй вызов использует результат первого. Всё остальное — водопад запросов, который на клиенте виден как «долго грузится».

### Публичная поверхность — по требованию

По умолчанию всё приватно. Экспорт появляется, когда есть второй потребитель, а не «на будущее»: каждый преждевременный экспорт становится вечным API, который никто не решается тронуть.

### Мёртвый код удаляется

Код без вызывающего удаляется, а не комментируется, не прячется за флаг и не остаётся «на всякий случай». Git помнит всё; закомментированный блок помнит только автор, и через месяц уже неточно.

## 5. Ошибки

**Два класса, середины нет.**

**Ожидаемый отказ** — часть контракта: не найдено, нет прав, истёк токен, не хватает средств. Возвращается типизированным значением с кодом вида `домен.предмет.причина`:

```
auth.token.expired
music.track.missing
billing.card.declined
```

**Неожиданный отказ** — нарушенный инвариант, недоступная БД, баг. Бросается. Ловит только граница процесса, которая умеет это записать и вернуть 500.

**`catch`, который логирует и продолжает, — запрещён.** Он превращает отказ в тишину, а тишину нельзя расследовать. Из `catch` есть ровно два выхода: пробросить дальше или вернуть типизированный отказ.

## 5.1. Провод: имена событий

Событие — **свершившийся факт**, а не команда. Сабджект читается как предложение в прошедшем времени: `v1.{домен}.{предмет}.{что произошло}`.

```
v1.user.email.verified        не  v1.user.verifyEmail
v1.billing.invoice.paid           v1.billing.payInvoice
v1.iam.role.granted               v1.iam.grantRole
```

Разница не косметическая: команду адресуют исполнителю, а факт публикуют в никуда. Имя в повелительном наклонении обещает, что кто-то обязан его выполнить, — и первый же сервис, который на него подписался «просто посмотреть», превращает шину в скрытый RPC.

Причастие берётся из закрытого списка (`event_verbs` в `grain.synx`) по тем же соображениям, что и словарь глаголов: `updated` и `changed` не должны означать одно и то же в разных доменах. Составной хвост допустим, если причастие остаётся последним словом: `v1.resonance.family.memberAdded`, `v1.iam.role.statusChanged`.

Заметьте: `update*` в коде запрещён, а `updated` в проводе — норма. Противоречия нет: в коде это неназванное действие, в проводе — название уже случившегося.

**Живой сабджект не переименовывают.** На него подписаны работающие консьюмеры, и правка имени — это не рефакторинг, а миграция: новый сабджект, оба публикуются какое-то время, потребители переезжают, старый снимается. Поэтому имя выбирают один раз и правильно.

## 6. Комментарии

Комментарий отвечает на «почему», никогда на «что». «Что» уже написано в коде строкой ниже, и оно не врёт — в отличие от комментария.

Разрешены пять тегов:

```ts
// why: Stripe шлёт webhook раньше, чем отдаёт объект в API
// perf: 40k строк — Map быстрее линейного поиска на два порядка
// safety: сравнение constant-time, значение приходит извне
// spec: RFC 8628 §3.5
// ref: инцидент 2026-08-04, откат прода
```

Продолжение многострочного комментария тег не повторяет. Блочный комментарий — только JSDoc над экспортом; `/* ... */` вокруг кода означает, что код надо удалить, а не закомментировать.

**Запрещено:** комментарий-пересказ кода, `TODO` / `FIXME` / `HACK`, нумерация шагов, ASCII-разделители, эмодзи (в комментариях и в логах — лог читает `grep`, а не человек).

Осознанное исключение из любого правила оформляется явно и с причиной:

```ts
// grain:allow unit-suffix — поле внешнего контракта Stripe, переименовать нельзя
```

## 7. Файлы и каталоги

### Роль в имени файла

`<домен>.<роль>.ts` — роль видна в листинге каталога, файл не нужно открывать.

| Роль | Содержимое | Обещание |
|---|---|---|
| `*.entry.ts` | Точка входа процесса | Единственное место, где собирается граф зависимостей |
| `*.route.ts` | HTTP-эндпоинты | Только разбор запроса и вызов домена |
| `*.rpc.ts` | gRPC-методы | То же для RPC |
| `*.store.ts` | Доступ к БД | **Единственное место, где есть SQL/ORM** |
| `*.wire.ts` | Клиент к чужому API | Единственное место, где живёт чужой формат |
| `*.policy.ts` | Правила доступа и инварианты | Чисто, без I/O — правила можно тестировать без БД |
| `*.shape.ts` | Типы и схемы валидации | Ничего исполняемого |
| `*.event.ts` | Контракты событий, продюсеры и консьюмеры | Имена сабджектов только здесь |
| `*.job.ts` | Фоновые задачи, крон | Идемпотентность обязательна |
| `*.pure.ts` | Чистые вычисления домена | **Ноль I/O.** Легальное место для того, что раньше сваливали в `utils` |

`*.tsx` — компонент по определению, роль не нужна. Имена, продиктованные фреймворком (`page`, `layout`, `route`, `middleware`, `mod`), остаются как есть. Публичный вход пакета — `public.ts`.

### Запрещённые имена файлов

`utils` `util` `helpers` `helper` `common` `shared` `misc` `lib` `main` `types` `constants` `service` `manager` `handler` `index`

Каждое из них — обещание свалки: файл с таким именем через полгода содержит две несвязанные вещи, и его никто не может удалить, потому что непонятно, кто им пользуется. У «утилит» есть законное место — `*.pure.ts` рядом со своим доменом.

### Каталоги — вертикальные срезы

```
src/track/track.route.ts      не   src/controllers/track.ts
src/track/track.store.ts           src/services/track.ts
src/track/track.policy.ts          src/types/track.ts
src/track/track.pure.ts            src/utils/track.ts
```

Каталог называется по домену, не по технической природе. Запрещены каталоги `utils helpers common shared misc lib core services controllers managers handlers`. По листингу `src/` должно быть видно, **что делает продукт**, а не на каком фреймворке он написан.

### Дерево, которое задаёт фреймворк

Под `src/app/` (и `src/pages/`) иерархия каталогов — это URL, а не решение автора: `app/api/auth/twofa/route.ts` глубже предела не потому, что кто-то поленился, а потому что так адресуется эндпоинт. Предел глубины там не считается — каталоги перечислены ключом `dirs_framework`. Правило о домене вместо техники продолжает действовать: `app/api/auth/` — это адрес, `app/utils/` — по-прежнему свалка.

## 8. Анти-отпечаток

Отдельная глава, потому что это отдельная проблема.

Код, написанный языковой моделью без стандарта, узнаётся мгновенно: не по ошибкам, а по **тяготению к середине распределения**. Модель выбирает самое вероятное имя (`handleData`, `processItems`, `utils.ts`), самый вероятный комментарий (пересказ следующей строки), самую вероятную защиту (`try/catch` вокруг чистой функции). Получается код без автора.

Правила выше убирают это как побочный эффект: закрытый словарь глаголов физически не содержит `handle`, теговые комментарии не позволяют пересказ, роли файлов не оставляют места для `utils.ts`. Дополнительно запрещено:

| Тик | Почему |
|---|---|
| Эмодзи в коде, логах, коммитах | Лог читает `grep` |
| `// Шаг 1:`, `// Step 2:` | Пересказ потока управления |
| JSDoc, повторяющий сигнатуру | Типы уже написаны и проверяются компилятором |
| `const result = await x(); return result` | Переменная на одну строку |
| `?.` там, где тип не допускает `null` | Защита от невозможного маскирует настоящие баги |
| `try/catch` вокруг чистой функции | Чистая функция не отказывает |
| `// ============` | Структуру задаёт разбиение на файлы |
| `Enhanced`, `Advanced`, `V2` в именах | Оценка вместо описания |

Правило, из которого всё это следует: **у каждой строки есть причина, которую автор может назвать вслух.** Строка, которая есть «на всякий случай», удаляется.

## Что GRAIN сознательно не регламентирует

Стандарт, который лезет во всё, перестаёт быть инженерным документом.

| Не наше дело | Почему |
|---|---|
| Отступы, кавычки, точки с запятой, длина строки | Работа форматтера. Спор об этом не стоит ни одной минуты |
| Выбор библиотек и фреймворков | Зависит от задачи и меняется чаще, чем стандарт |
| Слоистая архитектура, DDD, гексагоны | GRAIN задаёт направление зависимостей и роли файлов; какую школу поверх этого строить — решает команда |
| Стиль коммитов и ветвление | Другой документ, другая дисциплина |
| Покрытие тестами в процентах | Метрика, которой легко соврать |

## Как спорить со стандартом

Правило, которое мешает, — повод его изменить, а не тихо обойти.

1. Приведи код, где правило делает хуже. Не описание, а код.
2. Предложи правку `grain.synx` и этого документа — одним изменением, они меняются только вместе.
3. Пока правка не принята — работает `// grain:allow <правило> — <причина>`. Причина обязательна: она и есть аргумент в споре.

Стандарт без процедуры изменения превращается в скрижаль, а скрижаль обходят молча.

## Версии и совместимость

GRAIN версионируется целиком: `1.0`, `1.1`, `2.0`. Словари могут пополняться в минорной версии, **сокращаться — только в мажорной**: удаление глагола ломает существующий код.

**1.1** — границы: время, случайность и окружение только в ролях `entry route rpc job wire`; зависимости направлены внутрь; независимые `await` через `Promise.all`.

**1.2** — стандарт стал исполняться, а не только описываться. Ни одного нового запрета: чекер сам гоняет правила по AST (отдельный `eslint.config.js` в сервисе больше не нужен), долг легаси записан числами в `baseline.synx` и `adopt` накрыл весь код, появились [Kotlin и Swift](mobile.md), `grain --audit` проверяет, заслужен ли объявленный уровень. Новые ключи-данные: `dirs_framework` (иерархия, заданную фреймворком, не считаем), `units_foreign` (единицу в CSS задаёт чужой контракт), `paths_ignored` (сгенерированный код), `files_checked`. Исправлено: предикаты `is*`/`has*` отвергались словарём глаголов, `CONSTANT_CASE` разбирался посимвольно, `catch` с ветвлением без броска считался действием.

Правило, которого нет в [`grain.synx`](../grain.synx), не проверяется машиной; правило, которого нет в этом документе, не имеет смысла. Меняются оба файла одновременно или ни один.

Как включить проверку и как мигрировать существующий код — [enforcement.md](enforcement.md).
